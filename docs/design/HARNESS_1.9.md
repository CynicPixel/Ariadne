# Design — Phase 1.9: evaluation harness v1 (one report per run chain, every §30.2 metric)

Plan 1.9: "ATE/RPE vs GT (Umeyama alignment, `evo` as oracle), bytes by class, route validity vs GT; one
auto-generated report page per run (§30, §36)." The Phase 1 exit gate: "every metric in §30.2 emits a number
(however bad)", enforced by the D31 registry (`MissingMetrics(report).empty()`, no `UnknownMetrics`).

## What a "run" is in Phase 1

A replay **run chain**: the sim recording → `sim_collab` run (both agents' VO + 1.6 exchange + spool) → `recon`
run (1.7) → `mission` runs (1.8: merged + the two solo comparators). The harness takes the chain's directories,
reads only their committed outputs (results/eval YAML, CSV, TUM files), and writes one report directory:

```text
evaluation/runs/phase1/report/<chain id>/
  report.yaml        27 registry ids -> value, each with its definition, unit and source file (raw metrics)
  report_check.txt   ariadne_report_check output: MissingMetrics / UnknownMetrics, exit status (the gate)
  oracle.yaml        evo 1.31.1 APE/RPE on the same merged trajectory vs ours (must agree to 1e-6 relative)
  report.html        the page: summary, the 27 metrics by group, figures, provenance (self-contained)
  figures/*.png      generated by the harness (never hand-edited, §36), each from a function in the harness
  inputs.yaml        every input path + sha256 + its manifest's git commit/dirty; harness commit; command
```

The registry stays the single source of truth: a small C++ tool (`ariadne_report_check`) loads report.yaml and runs
`MissingMetrics` / `UnknownMetrics` from `metric_registry.hpp`; the Python harness never re-lists the ids.

## Metric definitions (fixed before computing; literature-standard where one exists)

| id | definition (this harness) | basis |
|---|---|---|
| ate_rmse_m, ate_rotation_rmse_rad | merged two-agent trajectory (agent 1 through T_O0_O1), ONE SE(3) Umeyama alignment, positions; rotation = angle of R_gt^T R_align R_est | Sturm et al. IROS 2012 (TUM RGB-D); D31; evo APE |
| rpe_translation_rmse_m, rpe_rotation_rmse_rad | per agent, pairs (i, i+20) for EVERY i (20 frames = 1 s at 20 Hz; the C++ `rpe_1s` pairing = evo `all_pairs=True, delta_unit=frames`), errors pooled over both agents | Sturm 2012; Zhang & Scaramuzza IROS 2018 |
| inter_agent_rpe_m | RMSE of the translation error of the exchanged, verified inter-agent edges vs GT | 1.6 candidates.csv |
| closure_precision | correct / accepted over every pair the verifier ACCEPTED (exchange + negative probe; correct = within 5 cm / 1°): the verifier's precision, keeps the probe's false accept visible | standard precision |
| false_closure_rate | incorrect / exchanged edges: wrong closures that reached the map (denominators the harness cannot inflate by adding easy probes) | `[ASSUMPTION]` |
| chamfer_m, completeness | fused cloud vs GT mesh samples: mean of accuracy and GT→cloud distance; fraction of GT within 5 cm | NICE-SLAM / iMAP-style accuracy / completion / completion ratio |
| coverage | merged mission map: GT-free cells observed free | 1.8 eval |
| heldout_psnr_db, heldout_ssim, heldout_lpips | 1.7 held-out renders of the (untrained) initialization | Wang et al. 2004 (SSIM); Zhang et al. CVPR 2018 (LPIPS, AlexNet) |
| bytes_total, descriptor_bytes, local_feature_bytes, pose_graph_bytes | ByteLedger totals: all; GLOBAL_DESCRIPTOR; MATCH_REQUEST + MATCH_RESPONSE; POSE_EDGE + POSE_GRAPH | Invariant 6 |
| bytes_per_keyframe, bytes_per_verified_loop, bytes_per_map_area_m2 | total / keyframes (both agents); total / verified exchanged edges; total / merged map's observed-free area | §30.2 |
| time_to_first_usable_map_s | merged mission: first replan with ANY target→exit route at ρ_agent | `[ASSUMPTION]` "usable" = navigable for an agent |
| time_to_first_valid_egress_s, route_validity, route_confidence | merged mission: first replan with an all-observed-free route at ρ_responder; final egress route's GT-valid fraction; its support p5 | §22.2 |
| route_confidence_calibration | `[PROXY]` Brier score over this run's replan egress routes, (support_p5 − GT-valid fraction)²; support_p5 is not a probability and the routes are nearly identical, so this is NOT a calibration estimate (n routes / n distinct reported) | Brier 1950 |
| distance_travelled_m | both agents' GT path lengths (the estimated length reported beside it: VO jitter while parked would inflate it) | §30.2 |
| energy_proxy | `[PROXY]` GT path length + 0.25 m/rad · GT yaw travel, until the planner defines energy (§4.3) | placeholder |

## Oracle

Three, all must pass: (1) each agent's harness ATE/RPE equals its C++ `results.yaml` (6 printed digits); (2) the
merged ATE reproduces 1.6's committed `merged_two_agent_ate_rmse_m` and sample count; (3) `evo` 1.31.1 (the version
that reproduced 1.5) through its Python API: APE on the merged trajectory with agent 1's stamps offset by 10⁶ s (so
evo can never pair one agent's estimate with the other's GT), RPE per agent (delta 20 frames, all pairs) pooled from
evo's per-pair errors; relative difference ≤ 1e-6. Rotation angles use the stable atan2 form (arccos lost ~1e-6
relative at mrad level). Pinned analysis image `infra/docker/analysis.Dockerfile`.
