## FIX A: FAR planner start/goal connection

**Verdict: CONTRADICTS the claim "as FAR joins start/goal through its local planner".** The grid-lattice splice itself is a reasonable fix, but it has no FAR precedent in that form. Tag it `[DESIGN]`.

### What the paper says (arXiv 2110.09460, the version served by arxiv.org/pdf/2110.09460 on 2026-10-23; §III-C "Planning on V-Graph", PDF p.3)
> "Given the robot position p_robot and goal p_goal, we would like to search the v-graph G for the shortest path between p_robot and p_goal. The planner first add p_robot and p_goal as two vertices on the global layer L_global and connect them to the vertices in {P^l_global} with non-blocking visibility edges. Then, a breath-first search is run on L_global to propagate through E_global and find the shortest path between p_robot and p_goal, if a path is available."

The paper does not say what happens when the goal has no visibility edge.

What "attemptable" means (§III-C, PDF p.4):
> "the vertices in {P^l_global} that have established non-blocking visibility edges with p_robot form the free space, and the rest vertices in {P^l_global} form the unknown space. … we provide the option of searching in the combined space (free and unknown) for attemptable planning or in free space only for non-attemptable planning."

Where the local planner appears (§IV, PDF p.4):
> "The onboard autonomy system incorporates navigation modules … e.g., terrain analysis, and way-point following based on kinodynamic feasible trajectories generated by the local planner [34], as fundamental navigation modules and runs FAR planner at the top of the system."

Reference [34] is J. Zhang et al., "Falco: Fast likelihood-based collision avoidance…", JFR 2020. It is the downstream waypoint follower, not the mechanism that joins endpoints to the graph.

### What the code does (github.com/MichaelFYang/far_planner, commit 2799b6964c141cacd1c32a14b19bc7abffbe0e52, 2025-03-31)

**Goal connection.** `GraphPlanner::UpdateGoalNavNodeConnects` (`src/far_planner/src/graph_planner.cpp` L108–128) tries every graph node through `IsValidConnectToGoal` (L130–140). That function requires `IsConvexConnect`, the reduced-direction test, and `ContourGraph::IsNavToGoalConnectFreePolygon` (`contour_graph.cpp` L130–144). An edge is added only after the votes pass (`IsVoteTrue`).

The collision test checks only **observed** obstacle contours, so unknown space is passable. That is how the goal stays "attemptable": a goal in unknown space connects by straight line through the unknown.

Before connecting, `UpdateGoal` (L318–352) reuses an existing trajectory navpoint if one lies within `kNearDist` of the goal.

**Goal inside an obstacle.** `ReEvaluateGoalPosition` (L355–419) handles this case:
- If the original goal is not free, it runs a **4-connected BFS on `free_terrain_grid_`** to the nearest `FREE_BIT` cell and moves the goal there.
- It then applies `ContourGraph::ReprojectPointOutsidePolygons(current_goal_pos, kNearDist)`.

This BFS-to-free-cell step is the nearest FAR analogue of our lattice fallback. It moves the goal; it does not splice a path.

**When no path exists.** `PathToGoal` (L142–262), branch `// no valid path found` (≈L231–256):
```
if (is_global_path_init_ && path_momentum_counter_ < momentum_thred) { global_path = recorded_path_; ... }   // replay last path
else { if (is_autoswitch && is_free_nav_goal_) { ... "free navigation fails, auto swiching to attemptable navigation..."
          if (is_global_path_init_) {global_path = recorded_path_; ...} else { _nav_node_ptr = goal_ptr; } ... }
       ... "FAIL TO REACH GOAL"; GoalReset(); _is_fail = true; return false; }
```
So FAR has three fallbacks:
1. Replay the previous path while the momentum counter allows.
2. Switch from free-only to attemptable mode. With no prior path, this sends the goal itself as the waypoint. Only here does "the local planner handles it" fit, and only loosely: Falco is handed the raw goal.
3. Otherwise, declare failure.

There is no grid-A* splice from the goal to the nearest node.

**Robot connection.** `DynamicGraph::UpdateNavGraph` (`dynamic_graph.cpp` L127–137) connects the odom node through `IsValidConnect` to the near nodes and the new nodes. `IsValidConnect` (L225–292) also accepts:
- **trajectory connections**: navpoints are dropped along the driven path (`IsInterNavpointNecessary`, L42–60; `ExtractGraphNodes`, L62–70);
- contour connections through tight areas.

So the robot is always graph-connected through its own trajectory.

**Grid planner in FAR.** `TerrainPlanner::PlanPathFromPToP` (`terrain_planner.cpp` L78ff.) is an **8-connected grid A\*** restricted to a cylinder around the segment. It is used only in `ReEvaluateConnectUsingTerrian` (`dynamic_graph.cpp` L842–848, called at L105–118) to re-validate trajectory edges between internav nodes in non-static environments. It is not used for goal connection.

### Convex vertices and obstacle offset
**Paper (Alg. 1 line 6, PDF p.3):**
> "Check the inner angle of each vertex and eliminate the vertices with inner angle < ζ"

Prose (§III-A):
> "check the inner angle between the two connected edges on the contour for each vertex to infer the local curvature of the obstacle. The vertices with the inner angle less than a threshold are eliminated."

This is an inner-angle (sharpness) filter. The paper does not say "convex only".

**Code.** `node_struct.h` L12–17 defines `enum NodeFreeDirect {UNKNOW, CONVEX, CONCAVE, PILLAR}`. `DynamicGraph::IsConvexConnect` (`dynamic_graph.h` L509–514) returns true only if neither endpoint is `CONCAVE`. So concave nodes can exist, but they never get visibility edges. In effect only convex and pillar nodes carry edges.

**Reduced v-graph (§III-B, Fig. 3, PDF p.3):**
> "for the edges in E_local that are longer than a threshold, we neglect the unnecessary edges that head into the one or both connected polygons and keep the edges that 'pass around'"

Check whether our implementation has this pruning (`IsOutReducedDirs` in code).

**Offset.**
- Paper §III-A: "we first project S onto I and at the same time inflate the points in S using the vehicle size", i.e. configuration-space inflation.
- Code: `ContourGraph::ReprojectEdge` / `ProjectNode` (`contour_graph.h` L199–203) shift each endpoint along its free direction by `min(0.4·d, kProjectDist)` before collision checks, with `kProjectDist = voxel_dim`.
- Code: `kNavClearDist = robot_dim/2 + kLeafSize` and `kNearDist = robot_dim` (`far_planner.cpp` L468–472; `robot_dim` is 0.8 m in `config/default.yaml`).

### Recommended change
- Reword the comment and doc to something like: "FAR connects p_robot/p_goal to the v-graph by visibility edges checked only against observed polygons (§III-C). If the goal is blocked it reprojects the goal to the nearest free cell by grid BFS (`ReEvaluateGoalPosition`). If no path exists it replays the last path or attempts the goal directly. Our lattice splice is a `[DESIGN]` extension, not FAR behaviour."
- Possible root cause: see the cross-check under FIX D. Over-conservative LOS may have removed the goal's visibility edges in the 11.1 m case.

## FIX B1: CBBA bundle length L_t = 1

**Verdict: CONTRADICTS the rationale. Theorem 1 holds for any L_t.** Divergence from SGA at L_t = 2 means one of Theorem 1's conditions was violated, or there is an implementation or comparator bug. It is not a limitation of L_t > 1.

### Theorem 1 (Choi, Brunet, How, IEEE T-RO 25(4), 2009, §V-B, p.919), verbatim
> "**Theorem 1 (Convergence of CBBA):** Provided that the scoring function is DMG, the CBBA process with a synchronized conflict resolution phase over a static communication network with diameter D satisfies the following.
> 1) CBBA produces the same solution as SGA with the corresponding winning bid values and winning agent information being shared across the fleet, i.e.,
>    z_{i,j*_k} = i*_k ∀k ≤ N_min, y_{i,j*_k} = c^{(k)}_{i*_k, j*_k} ∀k ≤ N_min, ∀i ∈ I.
> 2) The convergence time T_C is bounded above by N_min D."

The conditions are: (a) every agent's score is DMG, (b) synchronized conflict resolution, (c) static network of diameter D. L_t enters only through N_min = min{N_t, N_u L_t} (§II-A, p.913), so the result covers any L_t.

The paper's SGA is Algorithm 4 (§V-A, p.917), which is L_t-aware:
> "Note that if η_i < L_t, the score update in lines 16 and 17 of Algorithm 4 …"

and p.918: "In case η_i = L_t for some agent i, all of the agent's scores for the next selection step become zero (line 12)."

**DMG definition (§IV-C.1, eq. (7), p.916):**
> "the value of a task does not increase as other elements are added to the set before it. In other words c_ij[b_i] ≥ c_ij[b_i ⊕_end b] … this paper will refer to this condition as diminishing marginal gain (DMG)"

**Consequence of DMG (eq. (9), p.917):**
> "In case the scoring scheme is DMG, the following relation is always satisfied: y_{i,b_in} ≥ y_{i,b_im}, if n ≤ m"

The paper argues the time-discounted reward (11) is DMG through the triangle inequality, eq. (12): "τ_ij(p_i ⊕_n {k}) ≥ τ_ij(p_i)".

**Release rule (§IV-B, eq. (6), p.916). This is exactly our "stale second-slot bid":**
> "If a bid is changed by the decision rules in Table I, each agent checks if any of the updated or reset tasks were in their bundle, and if so, these tasks, along with all of the tasks that were added to the bundle after them, are released: y_{i,b_in} = 0, z_{i,b_in} = ∅ ∀n > n̄_i; b_in = ∅, n ≥ n̄_i (6)"
>
> "Suppose that an agent is outbid for a task and, thus, releases it; then, the marginal score values for the tasks added to the bundle after this task are no longer valid. Therefore, the agent also needs to release all the tasks added after the outbid task. Otherwise, the agent will make further decisions based on wrong score values, which may lead to poor performance."

Note: y and z are reset for n > n̄ (the outbid task itself takes the incoming winner value), while the bundle is truncated from n ≥ n̄.

**What L_t = 1 actually does (§IV-B, p.916):**
> "CBBA can produce the same solution as CBAA for the problem with L_t = 1."

So with L_t = 1 we are running CBAA, with N_min = min{N_t, N_u}. **When N_t > N_u, tasks are left unassigned by each auction round.** This is a functional cost and must be stated wherever the default is documented.

### Known literature on CBBA failure with L_t > 1
- **Johnson, Choi, Ponda, How, "Allowing non-submodular score functions in distributed task allocation", IEEE CDC 2012, pp. 4702–4708** (MIT author manuscript).
  - PDF p.3: "It is simple to demonstrate that the distributed greedy multi-assignment problem may fail to converge with a non-submodular score function, even with as few as 2 tasks and 2 agents." Also: "In practice, any non-submodular score functions very often lead to fairly malicious cycling behavior."
  - PDF p.4, eq. (3): the common insertion score `R − f_i d_{x⊕j}` (reward minus fuel × increase in path length) is non-DMG. "This results in the bid on the second task being greater than the first task (R − f_i d_12 > R − f_i d_a1) which is exactly the situation shown in Example 2 for a non-submodular score function. Depending on bids made by other agents in the fleet this can easily lead to cycling."
  - **Fix (§III-B, eq. (6), PDF p.5):** "A bid warping function, G_ij(c_ij, b_i) = c̄_ij … c̄_ij = min(c_ij, c̄_ijk) ∀k ∈ {1,…,|b_i|}". Rank internally with the true score, but broadcast a bid capped by every earlier bid in the bundle.
- **Choi 2009, Lemma 4 (p.919):** for non-DMG scores, use "c_ij(t) = min{c^o_ij(t), c_ij(t−1)}" (eq. 34). This "creates a conflict-free assignment within N_min D iterations independent of scoring schemes. Moreover, if the score function is DMG, it generates the identical solution to SGA."
- **Buckman, Choi, How, "Partial Replanning for Decentralized Dynamic Task Allocation", arXiv 1806.04836v2, §IV-A:** "An important requirement for the tasks chosen for resetting is they must be the lowest tasks in each agent's respective bundles. … if tasks are reset in any other order (randomly chosen or maximum bids), CBBA will not have diminishing valued bids, and the team will not converge to a conflict-free solution."
- ACBBA (Johnson, Ponda, Choi, How, Infotech@Aerospace 2011): read for B2 below. I found no erratum of Choi 2009. [UNVERIFIED]: no exhaustive errata search was done.

### Recommended change
1. Find the cause rather than capping L_t:
   - **Is our score DMG?** An additive path-length or energy insertion score is not DMG (Johnson'12 eq. 3). Time-discounted reward with triangle-inequality travel times is DMG (Choi'09 eqs. 11–12).
   - **Is eq. (6) applied?** All tasks after an outbid or reset task must be released, including when the change comes from a "reset" rule in Table I.
   - **Does the SGA oracle apply the same L_t cap and marginal-score update** (Alg. 4 lines 12, 16–17)?
   - **Tie-breaking** must be the same systematic rule in both (p.915: "this paper assumes that ties … are resolved in a systematic way").
2. Add a runtime or test assertion of eq. (9): broadcast bids are non-increasing along every bundle. A violation is a DMG violation.
3. If the score is non-DMG, add bid warping (Johnson'12 eq. 6), which is equivalent to the Lemma 4 clamp. Then return to L_t ≥ 2. Keep L_t = 1 only as an ablation baseline (it is CBAA), and document that it leaves N_t − N_u tasks unassigned per round.

## FIX B2: convergence criterion

**Verdict: PARTIALLY SUPPORTS.** Quiescence is a valid stop rule in a synchronous, static simulation, and ACBBA uses the same notion. Two corrections:
- **"2 N_t D" is not in the paper.** The bound is N_min·D.
- **Do not include s in the no-change test.**

### Quotes
- Bound: Theorem 1(2), p.919: "The convergence time T_C is bounded above by N_min D." Also p.919: "Note that in many cases, CBBA converges much earlier than N_min D iterations…"
- Dynamic networks, §V-D, p.919: "the convergence time will then be upper bounded by Δ N_min, since any information about conflicts is transmitted within Δ."
- Definition, §V, p.917: "convergence means producing an assignment in finite time with all of the constraints in (1) being satisfied."
- The paper gives no runtime termination-detection rule.
- Buckman'18 §II-C paraphrases the bound as "O(n_t D) rounds of communication".
- **Timestamps change every message** (§IV-B, eq. (5), p.916): "Each time a message is passed, the time vector is populated with s_ik = τ_r if g_ik = 1; max_{m: g_im = 1} s_mk otherwise, where τ_r is the message reception time."
  - So s_ik for every neighbor k advances every round, even at a fixed point of (y, z, b).
  - If the no-change test includes s, it may never fire, and we silently fall back to the round cap. The test must compare (y, z, b, p) only, or s relative to the round index.
- ACBBA (Johnson, Ponda, Choi, How 2011, p.7 of 12 / PDF p.8): "In a static environment ACBBA is guaranteed to converge. … Once the network goes quiet in this configuration we say that the network has converged." PDF p.9: "it does not make sense to define the idea of global convergence for ACBBA"; agents instead use a local "separation time".

### Why one quiet round suffices here
This is my reasoning, not a paper quote. With synchronous rounds, a static graph, and deterministic agents, if no agent's (y, z, b) changed in a full round, every agent receives the same messages next round and produces the same state. The state is a fixed point. This holds only for a globally observed simulation. On a real decentralized system no agent can observe global quiescence (cf. ACBBA local convergence).

### Recommended change
- Stop on "one full synchronous round with no change in (y, z, b) for any agent", excluding s.
- Keep a logged hard cap at N_min·D, using D ≤ N_u − 1 when the diameter is unknown. Hitting the cap means a Theorem-1 assumption was violated (non-DMG score, asynchrony or a bug). Log it as such, not as normal termination.

## FIX C: D* Lite trigger for new obstacles

**Verdict: SUPPORTS the split, as long as every changed edge still reaches UpdateVertex. Labelling an event "new_obstacle" is our `[DESIGN]`.**

### Quotes
- Koenig & Likhachev, AAAI 2002, "D* Lite", p.4: "It does not make any assumptions about how the edge costs change, whether they go up or down, whether they change close to the current vertex of the robot or far away from it, or whether they change in the world or only because the robot revised its initial estimates."
- AAAI 2002 Fig. 3 main loop: "Scan graph for changed edge costs; if any edge costs changed … for all directed edges (u, v) with changed edge costs: Update the edge cost c(u, v); UpdateVertex(u)". The optimized version has the same lines {36″–42″}, p.5.
- T-RO preprint, Fig. 5 "D* Lite: Second Version", lines {28′}–{35′}: "Scan graph for changed edge costs; if any edge costs changed; km = km + h(s_last, s_start); s_last = s_start; for all directed edges (u, v) with changed edge costs; Update the edge cost c(u, v); UpdateVertex(u); ComputeShortestPath();"
- T-RO preprint, Fig. 9 "(optimized version)", lines {41″}–{47″}: "c_old = c(u, v); Update the edge cost c(u, v); if (c_old > c(u, v)) rhs(u) = min(rhs(u), c(u, v) + g(v)); else if (rhs(u) = c_old + g(v)) if (u ≠ s_goal) rhs(u) = min_{s′∈Succ(u)}(c(u, s′) + g(s′)); UpdateVertex(u);"
  - The algorithm distinguishes cost **decrease** from **increase**, and both must be processed.
- How to detect changes is not specified beyond "Scan graph for changed edge costs". Comparing against the previous mask is a legitimate way to do this scan.

### Recommended change
- Make sure that **every** changed edge cost reaches UpdateVertex, together with the k_m/s_last update. That includes blocked → free (a cost decrease) and plain cost changes. This must hold even when neither "new_obstacle" nor the cost-change trigger fires for that case (for example, a cell that clears).
- The event labels can stay split for the decision trace, but the propagation set must be the full diff.
- Remember that each cell change affects all edges incident to that cell: 4 or 8 neighbors, in both directions.

## FIX D: line of sight on a 4-connected raster

**Verdict: PARTIALLY SUPPORTS.**
- Requiring the line to be clear in both directions is **load-bearing for safety**: one direction alone misses cells the segment actually crosses.
- It is also **over-conservative**: it blocks cells the segment never touches.
- The standard symmetric choice is to enumerate the cells the segment geometrically crosses (Amanatides & Woo traversal or a supercover) with an explicit corner rule.

### Literature quotes
- **Amanatides & Woo, "A Fast Voxel Traversal Algorithm for Ray Tracing", Eurographics 1987.**
  - p.2: "To correctly traverse the grid, a traversal algorithm must visit voxels a, b, c, d, e, f, g and h in that order. … The new traversal algorithm breaks down the ray into intervals of t, each of which spans one voxel. We start at the ray origin and visit each of these voxels in interval order."
  - It "is a variant of the DDA line algorithm … ours has no preferred axis."
  - p.3 inner loop: `if(tMaxX < tMaxY) { tMaxX += tDeltaX; X += stepX; } else { tMaxY += tDeltaY; Y += stepY; }`. At an exact corner (tMaxX == tMaxY) the strict `<` always steps Y first. So A&W's tie rule is also direction-dependent at exact corner crossings, and needs an explicit symmetric corner rule.
- **Theta\***. The AAAI 2007 paper (Nash, Daniel, Koenig, Felner) defines LOS only abstractly: "lineofsight(s, s′) is true if and only if they have line-of-sight" (p.2). The implementation is in **Daniel, Nash, Koenig, Felner, "Theta\*: Any-Angle Path Planning on Grids", JAIR 39 (2010) 533–579**:
  - §2, p.534: "Vertex s has line-of-sight to vertex s′ … iff the straight line from vertex s to vertex s′ neither passes through the interior of blocked cells nor passes between blocked cells that share an edge. … For simplicity, we allow a straight line to pass between diagonally touching blocked cells."
  - App. A, pp.570–571: "Performing a line-of-sight check is similar to determining which points to plot on a raster display when drawing a straight line between two points. The plotted points correspond to the cells that the straight line passes through. … two vertices have line-of-sight iff none of the plotted points correspond to blocked cells. This allows Basic Theta* to perform its line-of-sight checks with the standard Bresenham line-drawing algorithm" (Algorithm 6, lines 106–151).
  - Theta*'s vertices are **cell corners**, not centers. Its LOS is a geometric predicate (interior crossing plus the shared-edge squeeze rule), so it is symmetric by definition.
- "Supercover" line literature (e.g. E. Andres's discrete-line work): [UNVERIFIED]. Not read in this session.

### Our numerical check (own evidence, not literature)
Method:
- I ported OpenCV `LineIterator::init` and `operator++` with connectivity 4 to Python. Source: `opencv/5.x` branch, `modules/imgproc/src/drawing.cpp` L160ff. and `include/opencv2/imgproc.hpp` L4638–4652, as fetched on 2026-10-23. [ASSUMPTION]: this matches our pinned OpenCV 5 tag. Not checked against the installed build.
- Test set: segments between cell centers, from (0,0) to every (dx, dy) with |dx|, |dy| ≤ 12. That is 624 segments.
- Compared against the exact open cover (cells whose interior the segment crosses) and the closed cover (cells the segment touches).

| measure | count / 624 |
|---|---|
| a→b and b→a give different cell sets | 392 |
| one direction **misses** at least one interior-crossed cell (unsafe) | 272 |
| union of both directions misses an interior-crossed cell | **0** |
| union contains a cell the segment does not even touch (over-blocking) | 272 |
| union exactly equals the closed cover | 352 |
| segments passing exactly through a cell corner (open ≠ closed cover) | 200 |
| `leftToRight=true`: symmetric | 624 (always) |
| `leftToRight=true`: misses an interior-crossed cell | 272 |

Example, from a=(0,0) to b=(3,1):
- forward: {(0,0),(1,0),(1,1),(2,1),(3,1)}
- reverse: {(0,0),(1,0),(2,0),(2,1),(3,1)}
- true interior crossing: {(0,0),(1,0),(2,1),(3,1)}; the segment passes exactly through the corner at (1.5, 0.5).

Conclusions:
- OpenCV's 4-connected iterator is **not** a supercover.
- One direction alone is unsafe.
- `leftToRight=true` buys symmetry but not safety.
- The union of both directions is safe in this sample and conservative even relative to the closed supercover. It never misses a crossed cell, but over-blocks in 272/624 cases. This is an empirical result for |d| ≤ 12, not a proof.

### Recommended change
Replace the double LineIterator with an exact symmetric traversal:
- Use Amanatides–Woo or an integer supercover between cell centers.
- At exact corner crossings (tMaxX == tMaxY), choose an explicit rule. Either block if **either** diagonal neighbor is blocked (conservative, safe for a robot of finite width with inflated obstacles), or Theta*'s rule (allow the diagonal squeeze, block only when the line runs between two blocked cells sharing an edge).
- Implement it so the result is independent of endpoint order, e.g. canonicalize endpoints first.

This gives the same safety as the current union with less over-blocking.

**Cross-check with FIX A:** over-blocking LOS removes visibility edges. That may be why the goal "sees no graph node" in the 11.1 m vs 4.4 m case. Worth re-running that case with an exact supercover LOS. Not blocking.
